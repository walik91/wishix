# Wishix

Нужны Docker и Docker Compose 2.22+. Все команды выполнять из корня проекта.
Общий порт страницы и API задаётся в `.env`: сейчас `APP_PORT=5173`.

Параметры БД тоже в `.env`: `DB_NAME`, `DB_USER`, `DB_PASSWORD` и `COCKROACH_IMAGE`. CockroachDB запускается автоматически в Docker с TLS; первый запуск создаёт БД и пользователя. Данные и сертификаты хранятся в постоянных томах и сохраняются после обычного `docker compose down`.

Compose-проект и сеть используют имя `wishix`, контейнеры и образы приложения — префикс `wishix-`. В `.env` заданы `DB_NAME=wishix` и `DB_USER=wishix`. Compose автоматически создаёт тома `wishix_db-data`, `wishix_db-node-certs` и `wishix_db-client-ca` для БД и TLS-сертификатов.

## Разработка

```sh
docker compose up --build --watch
```

Открыть <http://localhost:5173>. Изменения Vue сразу появляются в браузере, Go автоматически пересобирается. Логи видны в терминале; `Ctrl+C` останавливает запуск.

Гостевая главная: <http://localhost:5173/>. Рабочая регистрация и вход: <http://localhost:5173/register> и <http://localhost:5173/login> (`/sign-up` и `/sign-in` открывают соответствующие экраны). Регистрация требует подтверждения email кодом из письма; после подтверждения и входа открывается `/my`. Восстановление — `/forgot-password`. Сессии хранятся на сервере, выход и сброс пароля отзывают их. Страницы адаптивны и поддерживают EN/RU/RO. Google/Facebook подключаются позже.

В `.env` также нужны `APP_ORIGIN`, `AUTH_SECRET`, `AUTH_TRUSTED_PROXY_CIDRS` и настройки `SMTP_*`. Сейчас рабочий origin — `http://localhost:5173`, SMTP — предоставленный владельцем Zoho через STARTTLS. `AUTH_SECRET` создаётся один раз и сохраняется между запусками. Подробности настройки, API, предложенных параметров паролей/кодов и проверок — в [docs/AUTH.md](docs/AUTH.md). При старте сервер автоматически выполняет Goose `up`; HTTP запускается только после успешных миграций.

## Миграции Goose

Отдельная консольная команда собирается в Docker вместе с API. Для применения и проверки версии:

```sh
docker compose run --rm --build migrate up
docker compose run --rm migrate status
docker compose run --rm migrate version
```

Явный откат последней миграции: `docker compose run --rm migrate down`. Перед откатом остановить API: `docker compose stop server`. **Down первой миграции удаляет аккаунты и связанные данные.** Следующий запуск текущего API снова выполнит автоматический up; для работы на старой схеме сначала вернуть соответствующую версию кода. Есть также `up-by-one`, `up-to VERSION`, `down-to VERSION`, `redo`, `reset`.

Для production добавить `-f compose.prod.yaml` сразу после `docker compose`. Подробности перехода со старой схемы, проверки пустой БД и написания новых миграций — в [docs/MIGRATIONS.md](docs/MIGRATIONS.md).

Прежняя техническая страница проверки соединения сохранена по адресу <http://localhost:5173/status>.

Гостевые страницы используют общий layout: шапку с навигацией, контейнер шириной до 1120 px и подвал. После входа в гостевой шапке появляется «Моё». Ссылки «Как это работает» и «Вопросы» ведут к разделам главной.

Общая главная `/` доступна гостям и авторизованным пользователям. После входа на ней остаётся кнопка «Моё», а обе основные кнопки меняются на «Перейти к моим желаниям» и ведут прямо на `/my`. Гостю они предлагают регистрацию. Успешный вход и подтверждение регистрации открывают «Моё»; сам переход на `/` больше не вызывает перенаправление.

У `/my` собственная оболочка по дизайн-системе: боковая навигация на desktop, нижняя — на mobile/tablet. Здесь показана реальная коллекция «Все желания»: можно добавить желание на отдельной странице `/my/wishes/new` и удалить его с подтверждением. Название обязательно; описание, примерная цена с валютой и магазинные ссылки необязательны. Данные сохраняются в CockroachDB и доступны только владельцу. Списки, редактирование желаний, изображения и автозаполнение по URL — последующие этапы. Подробности API и проверок — в [docs/WISHES.md](docs/WISHES.md).

Username и email берутся из текущей серверной сессии; окно «Профиль» показывает эти данные и позволяет выйти. Поиск, подписки и редактирование профиля ещё не подключены. Демонстрационные данные не подставляются. Inter раздаётся локально вместе с приложением.

Проверка API и соединения с БД: <http://localhost:5173/api/ready>.

После изменения `.env`, Docker-конфигурации или зависимостей остановить и повторить команду запуска.

## Запуск на сервере

Скопировать проект на сервер с Docker и настроить `.env`. Указать `APP_ORIGIN=https://<выбранный-хост>` и настроить внешний HTTPS-прокси, который направляет запросы на `APP_PORT`. Production требует HTTPS-origin для Secure-cookie и зашифрованный SMTP. Внешний домен в коде не закреплён.

```sh
docker compose -f compose.prod.yaml up -d --build
```

Приложение доступно по настроенному HTTPS-адресу. Vue собирается и раздаётся через Nginx; `/api*` обрабатывает Go. Контейнеры работают в фоне и перезапускаются вместе с Docker. Для обновления скопировать новый код и повторить ту же команду.

БД работает на одном узле вместе с приложением; отказоустойчивый кластер и резервное копирование ещё не настроены.

Логи и остановка:

```sh
docker compose -f compose.prod.yaml logs -f
docker compose -f compose.prod.yaml down
```
