# Поиск людей и имя

Поиск доступен авторизованному пользователю в `/my/search` по части username или имени. Поиск регистронезависимый; `%` и `_` обрабатываются как обычные символы. Результат содержит username для ссылки, имя и признак доступности публичного аватара. Личные и ссылочные списки поиском не раскрываются.

Имя обязательно и всегда публично: оно отображается в профиле и участвует в поиске. Для новых аккаунтов начальное имя равно username; пользователь может изменить его независимо от username. При смене username сохранённое имя не меняется. На странице публичного профиля отдельная подпись username не показывается, но username остаётся частью URL и доступен для поиска. Пустое или состоящее только из пробелов имя не принимается.

По решению владельца от 2026-11-19 прежний флажок публикации имени убран. Миграция 013 заполняет username только пустые имена существующих пользователей и сохраняет ранее введённые имена, включая ранее скрытые: теперь они публичны. Старое поле флажка сохранено в БД, но не влияет на выдачу и поиск; откат миграции не восстанавливает прежние пустые значения.

Рабочие параметры **предлагаются**: до 100 символов Unicode в имени и запросе, без управляющих символов; поиск по непустому запросу, до 20 человек на страницу, сортировка и курсор по username. Совпадение производится в CockroachDB через `lower` и `strpos`, с параметризованным запросом.

- `GET /api/search/people?q=...&after=...` — поиск для авторизованного пользователя; ответ `people` и `next_cursor`.
- `GET /api/profile/name` и `PUT /api/profile/name` — настройка `{display_name}` текущего аккаунта; мутация использует общие проверки Origin и JSON.
- `GET /api/public/profiles/{username}` возвращает имя, username и разрешённые публичные данные профиля.

Интеграционные тесты проверяют начальное имя, поиск по обоим полям, публичный профиль, валидацию и миграцию ранее созданных аккаунтов. Настройки аватара, возраста, описания и подписок описаны в [PROFILE_SOCIAL.md](PROFILE_SOCIAL.md).

Поиск подстроки сейчас выполняется без специализированного индекса; при росте числа аккаунтов потребуется измерить нагрузку и отдельно выбрать индексирование.
