# Изображения желаний

**Функция поручена владельцем 2026-11-04. Хранение и лимиты ниже предлагаются для текущего этапа.**

При создании желания можно выбрать одно необязательное изображение, увидеть предпросмотр, сменить или убрать выбор. Нажатие на миниатюру существующего желания открывает управление изображением: загрузку, замену и удаление. Отмена не отправляет файл. При сетевой ошибке выбор остаётся для повтора; карточка обновляется только после успеха. Изображения показываются целиком, с сохранением пропорций.

## Проверка и обработка

- JPEG, PNG и WebP, до 5 МиБ. Сервер проверяет действительный формат, не доверяя расширению или MIME файла. SVG, GIF, повреждённые и неподдерживаемые файлы отклоняются.
- До полного декодирования проверяются размеры: до 20 млн пикселей и до 8192 px по каждой стороне. Одновременно обрабатываются не больше двух multipart-запросов и двух декодирований; занятость возвращает `429 wish_image_busy`.
- Результат уменьшается до 1280 px по длинной стороне, без увеличения и обрезки. При необходимости используется меньший размер, чтобы получить JPEG до 512 КиБ. Прозрачность кладётся на белый фон. Учитываются все восемь EXIF-ориентаций JPEG.
- Сохраняется заново закодированное изображение. Исходные файлы, имена, EXIF и прочие метаданные не сохраняются. Временные uploads на диск Go-сервера не записываются.

## Хранение и доступ

Общий импорт по выбранной ссылке использует тот же процессор для скачанной картинки. Предпросмотр возвращает нормализованный JPEG в память браузера без записи в БД; обычное сохранение формы повторно проверяет файл. См. [URL_IMPORT_PROPOSAL.md](URL_IMPORT_PROPOSAL.md).

Goose `003_wish_images.sql` добавляет `wish_images`: один PK/FK `wish_id`, UUID-версия и `BYTES` с ограничением 512 КиБ. Создание желания, изображения и ссылок атомарно через существующий Transactor. Удаление желания каскадно удаляет изображение. Замена/удаление изображения ограничены владельцем в SQL. Код обработки — `internal/wishimage`, официальный `golang.org/x/image v0.47.0` используется для WebP и масштабирования.

Отдельная таблица с небольшим нормализованным файлом предлагается как простое решение текущего этапа без отдельного файлового сервиса и очистки потерянных файлов после отката. Объём изображений увеличивает нагрузку и резервные копии БД; при росте потребуется отдельный выбор объектного хранилища. Это не окончательно утверждённая архитектура хранения.

| Запрос | Поведение |
|---|---|
| `POST /api/wishes`, JSON | Прежний контракт без изображения |
| `POST /api/wishes`, multipart | JSON-поле `wish` и один файл `image` в любом порядке; атомарное создание |
| `PUT /api/wishes/{id}/image`, multipart | Один файл `image`; добавление/замена, ответ `{"image_url":"..."}` |
| `DELETE /api/wishes/{id}/image`, JSON | Удаление изображения, ответ `{"image_url":null}` |
| `GET /api/wishes/{id}/image` | JPEG только текущему владельцу; HEAD без тела |

DTO желания содержит `image_url` либо `null`, без бинарных данных и исходного имени файла. Версия в URL обновляет изображение после замены; она не является секретом и не заменяет проверку cookie-сессии. Без сессии — 401; чужой/отсутствующий файл — одинаковый 404. Изображение отдаётся как `image/jpeg` с `private, no-store`, `nosniff` и фиксированным именем `wish.jpg`.

POST/PUT/DELETE требуют настроенный Origin, `X-Wishix-Request: 1`, разрешённый Content-Type и отсутствие `Sec-Fetch-Site: cross-site`. Multipart читается потоком: метаданные до 48 КиБ, файл до 5 МиБ, весь запрос до 5 МиБ + 128 КиБ; неизвестные/повторные поля отклоняются. Большой файл возвращает `413 wish_image_too_large`, некорректный формат/размеры — 400 с `wish_image_invalid`/`wish_image_dimensions`. Production Nginx разрешает запросы до 6 МиБ, чтобы не блокировать допустимые файлы своим стандартным лимитом. Содержимое файлов не логируется.

Гостевое чтение изображения разрешено отдельно через POST `/api/public/lists/image` с token и wish_id. SQL проверяет видимость списка и членство желания; прямой GET владельца остаётся приватным. При удалении/закрытии списка или удалении желания из списка новые гостевые запросы перестают получать изображение. Изменение изображения общего желания видно во всех его списках. См. [LISTS.md](LISTS.md).

## Проверки

Сборка Go включает unit-тесты формата, лимита пикселей до декодирования, уменьшения, прозрачности, EXIF и удаления исходных данных. `docker compose -f compose.auth-test.yaml run --rm go-tests` проверяет создание/замену/удаление, приватность, CSRF, порядок multipart, повреждённые/большие/повторные файлы и откат желания со ссылками при ошибке хранения изображения. Миграционный откат изображений сохраняет желания и аккаунты.

В изолированной среде с Mailpit прошли 50 браузерных сценариев: JPEG/PNG/WebP, предпросмотр/отмена, ошибки и повтор, сохранение после перезагрузки, второй аккаунт, EN/RU/RO на 320/390/768/1024/1440 px. Проверена загрузка более 1 МиБ через production Nginx на временном `localhost:5175`. Скриншоты: `design/preview/wish-images-390.png`, `wish-images-1440.png`, `wish-image-form-390.png`, `wish-image-form-1440.png`; записи и файлы созданы только в тестовой среде.
