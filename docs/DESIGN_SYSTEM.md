# Wishix · Design System v1.0

Статус: **утверждено направление дизайна** (03.11.2026). Основа — первый визуальный макет с фиолетовой подарочной коробкой. Этот файл — дизайн-контракт, а не продуктовая спецификация.

## 1. Характер бренда

Wishix — сервис личных списков желаний, которыми удобно делиться. Он ощущается тёплым, дружелюбным и современным. Интерфейс **не должен выглядеть как интернет-магазин или тяжёлая административная панель**.

Стилистические опоры:
- много чистого пространства, чистые белые поверхности;
- мягкие сиреневые/кремовые подложки, розовый как редкий акцент;
- заметные фиолетовые основные действия;
- дружелюбные круглые формы, аккуратные тонкие иконки;
- декоративные подарки и банты только в hero/onboarding/empty state, а не у каждой кнопки;
- доступность и читаемость важнее визуального совпадения с сгенерированной картинкой.

## 2. Логотип

**Утверждённый образ:** слегка наклонённая квадратная фиолетовая подарочная коробка с бантом сверху, белой лентой и белым сердцем на передней стороне, несколько маленьких золотистых лучей справа. Основная надпись: `Wishix`, тёмное начало `Wish` и фиолетовое продолжение `ix`.

Для продукта использовать в первую очередь знак с текстом в шапке и знак отдельно для favicon/app icon. На тёмном фоне применять светлую текстовую версию. Не растягивать, не менять произвольно цвета, не заменять generic gift emoji.

**Файлы:** `design/assets/logo-mark.svg`, `logo-lockup.svg`, `logo-lockup-light.svg` для тёмного фона, `app-icon.svg`, растровые аналоги. Эти файлы — векторная **интерпретация** формы; оригинальный пиксельный образ см. в `design/reference/original-logo-crop.png` и основном макете. Точный production-мастер логотипа ещё не создан. Размеры: знак в desktop header ≈28–36 px, в mobile header 24–30 px, минимально 20 px; текст логотипа около 18–22 px. Вокруг логотипа оставлять свободное поле не менее ¼ высоты значка.

## 3. Цветовая система

| Роль | HEX | Использование |
|---|---|---|
| Primary | `#6B4EFF` | главное CTA, активная навигация, ссылки |
| Primary hover | `#5939E9` | hover на основных кнопках |
| Primary pressed | `#492EC7` | pressed/active |
| Secondary lilac | `#A78BFA` | вторичные заливки, небольшие элементы |
| Lavender | `#EDE9FE` | фон активных пунктов меню, мягкие панели |
| Warm cream | `#FFF7ED` | тёплая подложка hero и отдельных секций |
| Peach | `#FF8FA3` | иконка сердца и небольшие декоративные акценты; **не для мелкого текста на белом** |
| Text primary | `#1F1B3A` | заголовки, основной текст |
| Text secondary | `#5B5875` | подписи, вспомогательный текст |
| Border | `#E9E6F4` | границы карточек и полей |
| Surface | `#FFFFFF` | основные карточки и контейнеры |
| App background | `#FBFAFF` | основной фон приложения |
| Focus | `#4C2FC7` | видимое кольцо фокуса |
| Error | `#B42318` | текст ошибок; отдельный смысл, не peach |
| Success | `#18794E` | подтверждения; отдельный смысл |

Цвета в `design/tokens.css` — источник истины для программной реализации. Стараться использовать названия ролей (`primary`, `surface`, `text-muted`), а не разбросанные HEX в компонентах.

Контраст: `#FF8FA3` не используется для обычного текста на белом. Белый текст на CTA должен обеспечивать AA для нормального текста; нестандартные фоны проверять инструментально.

## 4. Типографика

- Семейство: **Inter**; fallback `system-ui, -apple-system, Segoe UI, sans-serif`.
- Заголовок H1 desktop: 30–32 px / 1.2 / 700–800; mobile 24–26 px.
- Заголовки секций: desktop 22–24 px / 1.3 / 700; mobile 18–20 px.
- Заголовки карточек: 14–16 px / 1.35 / 600–700.
- Основной текст: 14–16 px / 1.5 / 400.
- Вторичный текст: 12–14 px / 1.45 / 400–500.
- Кнопки: 14–16 px / 600; заголовок логотипа около 22 px / 800.
- Не делать мелкий текст ниже 12 px. Не использовать длинные строки и большое количество текста капсом.
- Для дат/чисел использовать табличные цифры там, где они сравниваются в столбцах.

## 5. Геометрия, сетка и глубина

### Скругления

- Поле/кнопка: 12–14 px; основная CTA может быть 14–16 px.
- Карточка: 16–18 px.
- Hero/большая панель: 20–24 px.
- Chips/теги: 9999 px (pill).

### Отступы

Базовый шаг: **4 px**. Основные интервалы: 8, 12, 16, 20, 24, 32 и 40 px. Контентные края: mobile 16 px, tablet 24 px, desktop 24–32 px. Межкарточный gap: 12–16 px. Внутренний padding карточки: 12–16 px (большой — 20–24 px).

### Тени и границы

- Карточка: `0 4px 18px rgba(42,29,91,.06)` + тонкая граница `#E9E6F4`.
- Панель: `0 12px 28px rgba(42,29,91,.09)`.
- Не использовать чёрные насыщенные тени, толстые бордюры, чрезмерный glassmorphism.
- Фон может иметь очень слабые лавандовые свечения, но контент не должен терять чёткость.

### Изображения

- Фото/изображения списков: единый радиус 10–12 px, `object-fit: cover`.
- Изображения желаний должны сохранять пропорции, по умолчанию `object-fit: contain`, если есть риск обрезать товар.
- Отсутствие картинки → аккуратный нейтральный placeholder (иконка подарка/сердца), не случайное изображение.
- Декоративные hero-иллюстрации не являются информационными и должны иметь пустой alt или `aria-hidden`.

## 6. Компоненты

### Button

- Primary: фиолетовый фон, белая надпись, скругление 14 px, высота 44–48 px, горизонтальные поля от 16 px.
- Secondary: очень светлый лавандовый фон, фиолетовый текст.
- Ghost: прозрачный фон, фиолетовый текст/иконка; только вторичные действия.
- Destructive: отдельный семантический стиль ошибки, не pink accent.
- На мобильном touch targets **не менее 44×44 CSS px**.
- Состояния: default, hover, pressed, focus-visible, disabled, loading; disabled не должен маскироваться под обычную кнопку.

### Navigation

- Desktop: слева вертикальная навигация около 232–248 px, справа рабочая область. Активный раздел — светло-лавандовый фон и фиолетовая иконка/текст.
- Mobile: компактный header + нижняя навигация со значками и подписью; учитывать `env(safe-area-inset-bottom)`.
- Состав пунктов **должен соответствовать действительным функциям в `docs/PROJECT.md`**, а не буквально повторять демонстрационный скриншот.

### Card: List и Wish

- ListCard: миниатюра/обложка, название, вторичная строка, контекстное меню; 3 карточки в строке desktop при достаточной ширине, 1 колонка mobile по умолчанию.
- WishCard: изображение, название, короткая вторичная информация, необязательная цена/ссылка, действие по спецификации. Цена не превращает продукт в магазин.
- Текст может быть длинным. Для названий предусмотреть перенос и/или 2 строки с доступным полным названием.
- Favorite/Reserve/Share — разные сущности и действия; не смешивать только из-за сходства иконок.

### Form

- Input: высота минимум 44 px, border 1 px, radius 12 px, заметный focus ring 2–3 px.
- Поля должны иметь видимый label; placeholder — не замена label.
- Ошибка: текст рядом с полем + семантическая разметка; не только цвет.
- Modal desktop / Bottom sheet mobile — по смыслу сценария и платформе; фокус и закрытие по Escape для веба.

### Empty / Loading / Notification

- EmptyState: небольшая иллюстрация, короткое пояснение, одно главное действие.
- Skeleton / shimmer: деликатный, отключается при prefers-reduced-motion.
- Toast: нейтральный, success, error; текст понятный без обязательного прочтения цвета значка.
- Hover-подсветка не должна быть единственным способом раскрыть действие.

## 7. Hero и декоративные элементы

Основной приветственный hero — мягкая лавандово-розовая подложка с коротким заголовком, объяснением ценности и главным действием. Подарок справа, на узком экране иллюстрация может быть скрыта/уменьшена **без потери информации**.

**Не копировать слово в слово заглушку «Создай свой первый список» для пользователя, у которого списки уже есть.** Hero зависит от состояния продукта. Элементы со звездочками/сердцами использовать экономно.

## 8. Иконография

- Линейные контурные иконки 20–24 px, stroke около 1.8–2 px, округлые окончания.
- Для кнопок с маленьким текстом 18–20 px.
- Активная иконка может становиться залитой, если это последовательно во всём интерфейсе.
- Типовой набор: home, list, gift, heart, user, bell, share, link, calendar, settings, plus, more-horizontal.
- Использовать единый набор (например Lucide), без смешения нескольких визуально разных библиотек.

## 9. Доступность и локализация

- Навигация клавиатурой, `:focus-visible`, семантические HTML-элементы и доступные названия иконок.
- Не передавать статус одним только цветом.
- Минимальный target на touch — 44×44 px.
- Поддерживать текст длиннее демонстрационного (RU/RO/EN), без наложений и обрезки критичных действий.
- Учесть `prefers-reduced-motion` и системное масштабирование текста.
- Проверять мобильную клавиатуру, zoom, landscape и overflow.

## 10. Чего не делать

- Не рисовать корзину, checkout, фильтры по магазинам и маркетплейсную сетку без продуктового требования.
- Не вводить новые оттенки фиолетового, не менять основной шрифт от страницы к странице.
- Не ставить полупрозрачные тени на каждую строку и значок.
- Не растягивать иллюстрации и не генерировать новый логотип при создании каждой страницы.
- Не принимать из демо названия разделов, рубли, карточки Sony или «Анну» за продуктовые требования.

## 11. Визуальная приемка

- Скриншоты на ширинах 390 и 1440 px рядом с `design/reference/original-desktop-mobile.png`.
- На 320 px нет горизонтального скролла/скрытых обязательных действий.
- На 768/1024 px меню, сетки и кнопки перестраиваются без скачков.
- Логотип, фон, карточки, типографика, отступы, навигация совпадают **по стилю**, а не требуют буквального пиксельного совпадения с художественным коллажем.
- Проверены фокус, контраст, loading/empty/error, длинный текст, mobile safe area.

## 12. Управление изменениями

Изменять цвета, типографику или стиль логотипа только после согласования и с обновлением `design/tokens.css`, `design/tokens.json`, этого файла и контрольных скриншотов. Технические решения и продуктовые изменения вести в существующих документах проекта, не дублировать их здесь.
