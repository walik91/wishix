# Проверка приоритетных магазинов для импорта

**Дата: 2026-11-04. Статус: результаты исследования и уточнение предложения; парсер в приложении не реализован.**

Владелец предоставил пять ссылок. Исходный HTML получен обычным HTTP GET без авторизации, cookies и исполнения JavaScript магазинов. Все пять запросов вернули 200. Локальный разбор выполнен через инертный DOMParser в браузере с отключённой сетью; это не браузерная загрузка страниц. Дополнительно проверена одна карточка Enter из переданной категории.

Это проверка конкретных страниц из текущего окружения, а не гарантия работы со всем ассортиментом, регионами и будущими изменениями каждого магазина. Полные HTML-снимки, картинки и диагностические отчёты остались в игнорируемом `.cache/parser-audit/`; в Git они не включены.

## Изображения и существующий обработчик

Основные изображения Maximum, Darwin, Ultra, карточки Enter и альтернативное изображение Crafti скачаны и проверены реальным `wishimage.Processor`. Все пять успешно преобразованы в JPEG, проходят ограничения формата/пикселей/размера. Размеры проверенных источников — от 600×600 до 1280×1280; исходные файлы — примерно 14–158 КиБ, нормализованные — примерно 17–132 КиБ.

Для Crafti исправление адреса не угадывалось заменой расширения или частей пути: действующий URL взят из данных самой галереи. У Darwin фактические байты и Content-Type подтверждают WebP, несмотря на расширение. Это подтверждает необходимость текущего декодирования по содержимому и независимой проверки каждого URL картинки, включая внешний CDN.

## Уточнения к предлагаемой реализации

1. **Общее ядро достаточно для старта.** Для проверенных карточек всех пяти магазинов Product/Offer уже присутствует в исходном HTML. Headless-браузер для этих примеров не требуется.
2. **Определять тип страницы до заполнения.** Переданную категорию Enter использовать как отрицательную фикстуру: вернуть предупреждение о ссылке на раздел и предложить открыть конкретную карточку; ручное создание с этой ссылкой остаётся доступным. Одного `og:type=website` для определения категории недостаточно: такое значение встречается и у проверенных настоящих карточек Ultra/Crafti/Enter.
3. **Разделять идентификацию товара и выбор поля.** JSON-LD — основной источник цены/валюты и изображений; название сверять с H1/OG. Для Darwin выбирать чистое название, для Ultra сохранять признаки выбранного варианта из H1. Не вводить жёсткое требование точного Offer.url: у Maximum оно исключило бы правильный единственный корневой Product. При этом рекомендациям и спискам товаров нельзя доверять как основному Product.
4. **Для Crafti нужен небольшой адаптер галереи.** При неработающем общем кандидате извлекать URL из известного JSON-атрибута. Использовать JSON-декодирование, не `eval` и не выполнение JS. Этот источник предлагает только дополнительную картинку; цена остаётся из Offer. В прикладном JSON Crafti встречается число с двоичной погрешностью (`49.950000000000003`), тогда как Offer даёт точную десятичную строку.
5. **Ограниченный запас кандидатов изображения.** Одна итоговая картинка, до трёх уникальных кандидатов под общим deadline/лимитом запросов. Product/OG-дубликаты не скачивать повторно. После 404 или повреждённого файла пробовать следующий допустимый кандидат; отсутствие картинки не отменяет найденный текст. Все кандидаты, редиректы и CDN проходят одну SSRF-политику.
6. **Лимит HTML пока подходит.** Все шесть проверенных страниц укладываются в предложенные 2 МиБ распакованного HTML; у Darwin размер около 1,4 МиБ. Ограничение проверять потоково, а не по Content-Length.

## Проверки для будущей реализации

- Пять положительных упрощённых HTML-фикстур и отдельная отрицательная для категории Enter; полные маркетинговые страницы в тесты не копировать.
- Строковая/числовая цена в JSON-LD; MDL извлекается из данных, а не назначается по домену магазина. Исходные ссылки, язык и выбранный вариант сохраняются.
- Единственный корневой Product с Offer.url на главную; несколько Product, рекомендации и категория с OG-логотипом.
- Неполное/засорённое Product.name; H1 с памятью и цветом; повторный H1 мобильной/desktop-разметки не создаёт второй товар.
- Недоступная общая картинка, повторяющиеся кандидаты, успешная картинка из адаптера, WebP с расширением PNG, внешний CDN.
- Для запросов по пользовательским URL всё ещё обязательны отдельные тесты SSRF, DNS rebinding, редиректов, тайм-аутов и ограничений. Успешное исследование публичных страниц эти проверки не заменяет.

Рекомендуемый первый этап остаётся прежним: безопасный Go-fetcher → JSON-LD/OG/H1 → небольшой адаптер Crafti для галереи → существующая нормализация изображения → предпросмотр формы. Полная реализация и детали выбора полей ещё требуют отдельного поручения владельца.
