# Автозаполнение желания по ссылке

**Статус: реализовано по поручению владельца 2026-11-04.** Утверждено направление: один общий процесс для публичных сайтов и возможность узких адаптеров по подтверждённым проблемам. Имя файла сохранено для существующих ссылок. Численные ограничения ниже — предлагаемые рабочие параметры реализации.

## Поведение

- Первый валидный HTTP(S) URL запускает одну автоматическую попытку после паузы ввода 800 мс или выхода из поля. Кнопка справа от любой ссылки запускает импорт из неё, включая повтор. Другие ссылки автоматически не загружаются.
- Заполняются название, описание, одно изображение и пара примерная цена/валюта. Результат показывается временным toast. Исходная ссылка сохраняется как введена пользователем; редиректы не подменяют её.
- Форму можно заполнять и сохранять во время импорта. Изменённые вручную поля, включая явно очищенные, не перезаписываются. Цена/валюта заполняются только вместе, если ни одно из этих полей не изменялось вручную. Выбранная пользователем картинка имеет приоритет.
- Смена или удаление ссылки, по которой идёт запрос, отменяет его и исключает поздний ответ. При изменении или удалении источника прежние автоданные очищаются только в полях без последующих ручных правок. Успешный импорт из другой ссылки заменяет незатронутые пользователем автоданные; отсутствующие в новом результате прежние автоданные очищаются, чтобы не смешивать товары. Ошибка и категория сохраняют прежние данные. Новый запрос, сохранение и уход со страницы отменяют выполняющийся импорт.
- Частичный результат заполняет найденное. Категории/списки товаров получают отдельное сообщение без логотипа и случайной цены из карточек. Ошибки не запрещают ручное сохранение с той же ссылкой.
- Автоданные нужно проверить. Нет фонового обновления цены, сравнения предложений или замены картинки у сохранённого желания.

## Общий процесс

`controllers.ProductImport → services.ProductImport → productimport.Importer`.

1. Безопасный GET исходного HTML без исполнения JavaScript, cookies и авторизации пользователя. При отсутствии объявления кодировки валидный UTF-8 не преобразуется ошибочно в Windows-1252.
2. Инертный разбор через официальный `golang.org/x/net/html v0.62.0`. Основной источник — JSON-LD Product/Offer: корневые объекты, массивы, `@graph`, `mainEntity`, варианты ProductGroup. Внешний `@context` не загружается. Основной товар выбирается по URL, Offer URL, заголовку или единственному корневому Product; неоднозначные рекомендации не выбираются случайно. В типах Schema.org также распознаётся относительная к протоколу форма `//schema.org/Product`.
3. Резерв — Product microdata/RDFa, Open Graph/Twitter, H1/title. Совпадающий H1 сохраняет вариант товара и убирает мусорный суффикс JSON-LD. При нескольких разных H1 заголовок выбирается по title только при единственном совпадении. Описание берётся из выбранного Product в JSON-LD или единственного Product в microdata/RDFa; общие описания страниц не используются. Все текстовые поля перед выдачей проходят ограниченное декодирование HTML-сущностей и инертное извлечение текста, включая значения адаптеров: разметка, скрипты и содержимое iframe/object и других встраиваемых элементов отбрасываются. Произвольные iframe не загружаются; подтверждённое исключение Maximum описано ниже. Описание ограничено 5000 символами. Цена берётся только из предметных метаданных с явным трёхбуквенным кодом валюты. Символ `$`, рассрочка, аналитика и произвольные цифры текста не используются. Различающиеся цены Offer/AggregateOffer пропускаются. Десятичные строки обрабатываются без float и округления.
4. Изображения: Product → OG/Twitter → `image_src` и инертные JSON-атрибуты товара/галереи с полями image/photo/gallery. Последний резерв — `src` изображения, чей подробный `alt` начинается с выбранного названия товара длиной не менее 20 символов. Это общие резервы без привязки к домену. Дубли исключаются; проверяются не более трёх URL. Ошибка картинки не отбрасывает текст.
5. `wishimage.Processor` проверяет реальное содержимое JPEG/PNG/WebP, размеры и EXIF-ориентацию, уменьшает и заново кодирует JPEG без исходных метаданных. Возвращается одна картинка до 512 КиБ.

Для Maximum зарегистрирован узкий адаптер описания; другие домены обрабатываются общим процессом. Сайты, требующие JS, входа, CAPTCHA или блокирующие HTTP-клиентов, могут давать частичный результат или не импортироваться. Гарантии для всех страниц интернета нет. Подтверждённый сбой сначала воспроизводится, затем исправляется общий процесс или добавляется адаптер.

## API и хранение

`POST /api/wishes/import-preview`: приватная cookie-сессия, настроенный Origin, `X-Wishix-Request: 1`, JSON и проверка `Sec-Fetch-Site`. Тело до 4 КиБ, только `url` и `locale` (`en`/`ru`/`ro`; прочее → `en`); неизвестные поля и хвостовые значения отклоняются.

```json
{"url":"https://shop.example.com/product","locale":"ru"}
```

Ответ `200`: `status` (`ok`, `partial`, `empty`, `not_product`) и найденные `title`, `description`, `price` (точная десятичная строка), `currency`, `shop_name`, `image: {mime: "image/jpeg", data_base64: "..."}`. Отсутствующие поля пропущены. `Cache-Control: no-store`; HTML магазина, внутренние адреса и сетевые ошибки не возвращаются. Статус `ok` по-прежнему означает наличие названия, цены и картинки; отсутствие необязательного описания не делает результат частичным.

Ошибки: `401` — нет сессии; `403` — межсайтовый запрос; `400` — некорректный ввод/запрещённый URL; `415` — тип тела; `422 import_unavailable` — страница недоступна/непригодна; `429` — лимит/занятый обработчик; `503` — недоступность хранилища авторизации/лимитов.

Предпросмотр не создаёт желаний, изображений и черновиков в БД. Браузер превращает картинку в File и сохраняет обычным multipart POST `/api/wishes` после нажатия «Сохранить». Сервер повторно проверяет файл и атомарно сохраняет желание, ссылки и картинку. Закрытие формы не оставляет uploads. Счётчик запросов в БД используется отдельно от предметных данных.

## Безопасность — рабочие параметры

- Только публичные HTTP(S), стандартные порты 80/443, URL до 2048 байт, без userinfo, управляющих символов и служебных имён.
- При каждом соединении проверяются все DNS A/AAAA; смешанные публичные/внутренние ответы запрещены. TCP подключается к проверенному числовому IP без повторного DNS; TLS проверяет исходный hostname. Запрещены loopback/private/link-local/unspecified/multicast, metadata/CGNAT, специальные диапазоны, IPv4-mapped private и переходные IPv6-адреса.
- Каждый редирект и URL картинки проходит ту же политику. До трёх редиректов на ресурс. HTTP_PROXY/HTTPS_PROXY не используются.
- Общий срок — 15 секунд, ресурс — до 10 секунд, подключение/TLS — 4 секунды, заголовки — 6 секунд и до 32 КиБ.
- HTML до 4 МиБ после распаковки gzip, исходная картинка до 5 МиБ; лимиты применяются потоком. MIME и реальное содержимое изображения проверяются независимо. Лимит HTML увеличен после воспроизведения страницы товара размером около 2,3 МиБ; численный параметр предлагается.
- JSON-блок до 512 КиБ/32 уровней; обход HTML до 100 000 узлов/256 уровней. Нет eval, исполнения скриптов или скачивания embedded API.
- До двух импортов одновременно на процесс, до 20 попыток за 10 минут на аккаунт через атомарный счётчик CockroachDB. Ключ счётчика — HMAC. Отмена клиента отменяет исходящий запрос.
- По поручению владельца журналируется каждая обработанная попытка предпросмотра: исходный URL полностью, включая query и fragment, результат, коды причины, наличие полей и при необходимости HTTP-статус источника или ошибка загрузки изображения. Для собственных ссылок и ссылок бронирования, в том числе вложенных в параметры, сохраняется только origin внешнего адреса. Невалидные URL и URL с учётными данными не сохраняются. Тела страниц, сетевые ошибки с адресами и личность пользователя не пишутся. Параметры и фрагменты URL сторонних сайтов могут содержать личные данные или секреты; доступ к журналам должен быть ограничен. Запросы, отклонённые до чтения корректного JSON или авторизации, в журнал импорта не попадают. Журнал направляется в stdout приложения; срок хранения зависит от настройки окружения Docker.

## Адаптеры

Контракт `productimport.Adapter`: `Match(*url.URL) bool`, `Enrich(Document, Metadata) Metadata`. Document содержит финальный URL и инертное HTML-дерево, Metadata — результат общего извлечения. Первый совпавший адаптер дополняет/заменяет поля. Итог снова проходит нормализацию и общий безопасный загрузчик картинок.

При подтверждённой проблеме добавить точное сопоставление hostname/пути, HTML-фикстуру и тест изоляции от других доменов. Регистрация в Fx-провайдере `app.go`: `productimport.New(myAdapter{})`. Адаптер анализирует Document, не создаёт свой HTTP-клиент, не исполняет JS и не обходит общий загрузчик. Специфичный импорт может переопределить Metadata целиком.

`MaximumAdapter` применяется только к карточкам `maximum.md` / `www.maximum.md` с путём `/ru/<id>` или `/ro/<id>` и только если обычное описание отсутствует. Он проверяет единственный код товара, iframe именно внутри блока описания и точное соответствие URL `https://plus.maximum.md/RichContentViewer/Models/<код>/index.html?culture=<язык>`. Адаптер передаёт кандидата общему загрузчику, который после картинки запрашивает не более 1 МиБ HTML за 3 секунды, без редиректов, cookies и выполнения JS, с прежними проверками DNS и публичных адресов. Из единственного `main[role=main]` извлекается чистый текст до 5000 символов; длинный текст обрезается по границе слова с многоточием. При ошибке описание остаётся пустым, а остальные данные сохраняются. Это не общий переход по iframe и не гарантия для всех товаров магазина.

## Проверки

- Go unit: извлечение JSON-LD/OG/microdata/RDFa/вариантов, точные цены, неоднозначность, категории, инертный JSON, изоляция адаптера, резерв картинки и JPEG. Сетевые тесты локальные: SSRF, смешанный DNS, закрепление IP, private redirect, лимиты gzip/ответа, типы и отмена.
- Интеграционные тесты на отдельной CockroachDB: сессия, Origin, строгий ввод, бюджет и отсутствие записей желания/картинки при предпросмотре.
- `front/tests/wish-import.browser.mjs`: поздний ответ, ручные правки/очистка/картинка, смена источника, альтернативные ссылки, повтор, сохранение при ошибке/категории/загрузке и EN/RU/RO × 320/390/768/1024/1440. API перехватывается; аккаунты не меняются. Требуются Playwright и Chrome; команда `node front/tests/wish-import.browser.mjs` против тестового Vite на 5174. `PLAYWRIGHT_MODULE` при необходимости задаёт путь к модулю, `WISHIX_TEST_ORIGIN` — локальный адрес.
- Живой Go-импорт 2026-11-04: Maximum, Darwin, Ultra, Crafti и отдельный товар Enter вернули название, цену/MDL и нормализованную картинку; категория Enter — `not_product`. Адаптеры не потребовались. Сквозная проверка с реальным API и тестовой почтой подтвердила импорт Crafti, отсутствие записи до сохранения, сохранение 49.95 MDL и картинки, восстановление после перезагрузки и запрет гостевого доступа. Исходные страницы: [URL_IMPORT_AUDIT.md](URL_IMPORT_AUDIT.md).
- Живой Go-импорт 2026-11-19 страницы кресла smart.md: после поддержки `//schema.org/Product` получены название, 4535.00 MDL без подписки и обработанная картинка. Описание также присутствует в microdata и импортируется после расширения по поручению владельца. Это проверка конкретного товара и окружения, не гарантия для других страниц или будущих изменений магазина; адаптер не потребовался.
- Страница Dyson V16 на Maximum содержит в описании JSON-LD HTML-экранированный `iframe`; текст описания находится во внешнем документе iframe. Код iframe удаляется; для подтверждённого формата Maximum описание извлекается отдельным ограниченным запросом. Точечные тесты проверяют домены, путь, код и язык товара, редиректы, размер и отказ источника.
