# Wishix — Responsive & Screen Guidelines v1.0

Данный документ описывает **визуальные композиции**, не утверждает новые пользовательские функции. Любые экраны и действия проверять по существующему `docs/PROJECT.md`.

## Ширины и поведение

| Диапазон | Представление | Контент |
|---|---|---|
| 320–767 px | Mobile | компактная шапка, нижняя навигация, одна колонка, фиксированные снизу элементы только с учётом safe area |
| 768–1023 px | Tablet | адаптированный header или компактный sidebar; 2 колонки при наличии места, никакой принудительной desktop-ширины |
| ≥1024 px | Desktop | постоянный sidebar 232–248 px, header, рабочая область; карточки списков обычно 3 в ряд |

Breakpoint — инженерная отправная точка, а не жёсткий закон: если содержимое перестаёт помещаться раньше, нужно перейти на более компактный layout.

Ограничивать максимальную ширину основной области разумно: ~1280 px для содержимого, чтобы длинные строки не расползались. Внутренние отступы 16/24/32 px в зависимости от ширины.

## Основной экран (пример утверждённого художественного макета)

### Desktop

- Белая карточка-панель приложения на очень светлом фоне.
- Левый sidebar: логотип, пункты основного меню, главное действие снизу (если оно имеет смысл в состоянии страницы).
- Верхняя полоса справа: уведомления, аватар, профиль.
- Заголовок-приветствие и короткий поясняющий текст.
- Hero-баннер: текст слева, подарочная иллюстрация справа, большая primary CTA.
- Секция «Мои списки»: ряд карточек с обложками и небольшим количеством метаданных.
- Ниже — недавние желания/объекты по реальным сценариям.

### Mobile

- Компактная шапка с логотипом и доступными действиями.
- Приветствие, одна сильная CTA.
- Списки: вертикальные карточки на всю доступную ширину; миниатюра слева, текст справа.
- Снизу постоянная навигация с подписями, контент не перекрывается ею.
- На мобильном нет sidebar и многоколоночной товарной сетки из ecommerce.
- Пустые состояния — понятное описание и одно основное действие.

## Другие предполагаемые дизайн-паттерны (не продуктовые решения)

### Экран списка

Header с названием/описанием, действие «Поделиться» только согласно реальным правилам, карточки желаний с изображением и понятным контекстным меню. На desktop возможна сетка в 2–3 колонки; на mobile — одна колонка. При отсутствии изображений сохраняется красивая геометрия.

### Добавить/редактировать желание

Компактная форма, ясные подписи, максимум полезного вертикального пространства. Ссылки магазинов/изображения/другие поля показываются только если они предусмотрены `docs/PROJECT.md`. On mobile использовать полноценный экран или bottom sheet по сложности формы.

### Публичный список

Поделиться можно без привычного внутреннего сайдбара, но сохранить брендовый header, контейнер, карточки и доступные действия. Не раскрывать закрытые данные. Реальная логика приватности и гостевых ограничений — из продуктовой спецификации, не из визуального эскиза.

### Дизайн-состояния, которые обязательно предусмотреть

Loading, empty, error, success, long content, малое количество элементов, много элементов, отсутствие изображений, disabled, keyboard focus. Искусственные данные художественного макета не являются системой продуктовых состояний.

## Тестовая матрица

- 320 × 640 — минимальная узкая ширина;
- 390 × 844 — типовая мобильная;
- 768 × 1024 — планшет;
- 1024 × 768 — узкий desktop / широкий tablet;
- 1440 × 900 — основной desktop;
- 1920 × 1080 — широкий desktop.

Для всех: нет горизонтального скролла; обязательные действия доступны; интерфейс работает с RU/RO/EN и текстом на 30–50% длиннее референса; видимы focus и error; соблюдается контраст и доступность.
