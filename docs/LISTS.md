# Управление списками

**Объём утверждён владельцем и реализован 2026-11-04:** создание, просмотр, редактирование, состав, очистка, копирование, удаление, доступ по ссылке и публичный просмотр без регистрации. Бронирования и сообщения дарителям требуют отдельного этапа; их данных и каналов связи в приложении пока нет. Архивирования нет.

## Пользовательские сценарии

- «Списки» в навигации открывает `/my/lists`. Новый список создаётся на `/my/lists/new`, управление — `/my/lists/{id}`. Есть название, описание, необязательная календарная дата и видимость. По умолчанию — «По ссылке».
- «Управление списком» позволяет изменить поля, создать копию, очистить или удалить список. Очистка, удаление и замена ссылки требуют отдельного подтверждения. Отмена и ошибка сохраняют данные; устаревшая версия не перезаписывает новые изменения.
- В список можно добавить существующие желания из коллекции, с поиском по названию. Уже входящие желания не предлагаются повторно. Можно создать новое желание внутри списка: текущий список выбран автоматически, доступны дополнительные списки. При создании из «Все желания» выбор необязателен.
- У желания в общей коллекции есть действие «Списки желания»: можно одновременно изменить его принадлежность нескольким спискам, в том числе убрать из всех. Пока списки загружаются, сохранение нового желания в контексте списка недоступно. Если список удалён, можно явно продолжить в общей коллекции, сохранив заполненную форму.
- Желание и его изображение существуют один раз. Удаление из списка удаляет только связь. Очистка и удаление списка сохраняют желания в коллекции и других списках. Глобальное удаление желания из коллекции удаляет связи во всех списках; предупреждение прямо говорит об этом.
- Копия содержит ссылки на те же желания и описание, без даты события. Как новый список, по умолчанию доступна по новой ссылке. Независимые желания и изображения не создаются, исходный список не меняется.
- Статус «Получено» ещё не реализован: все существующие желания активны и входят в копию. При реализации этого статуса фильтрация полученных в SQL копирования и соответствующий тест обязательны. Брони не копируются; их будущая глобальная привязка к желанию сохраняет смысл при общих ID.
- Сортировка списков — новые сверху, желаний — по исходной дате создания, как в коллекции. Счётчики реальны, без демонстрационных данных.

## Доступ и гостевой просмотр

- Личный список и его изображения доступны только владельцу. Чужие/отсутствующие ID возвращают одинаковый 404. Все операции управления проверяют cookie-сессию на сервере, владельца нельзя передать в теле.
- В режиме «По ссылке» любой получатель ссылки видит только этот список и его желания без регистрации. Список не появляется в публичном профиле. Для личного списка действие «Поделиться» объясняет необходимость изменить доступ и не показывает рабочую ссылку.
- Публичный список дополнительно виден на `/u/{username}`. Профиль отдаёт только username и публичные списки; не отдаёт email, ID аккаунта, личные/ссылочные списки, их количество или общую коллекцию.
- «Все желания» остаётся отдельной приватной коллекцией. Её публикация флажком профиля ещё не реализована; никакой режим обычного списка не публикует коллекцию целиком. Общее желание видно в тех списках, которым пользователь дал доступ.
- Ссылку можно заменить: старая сразу перестаёт работать для новых запросов. Переключение в личный режим, удаление списка и удаление членства также проверяются при каждом гостевом запросе изображения. Уже увиденные посетителем данные невозможно отозвать из его памяти/сохранённых копий.

Ссылка для пользователя: `/{username}/wishlist/shared#<token>`. Username в адресе носит информативный характер: сервер определяет список и проверяет доступ по токену. После успешной загрузки клиент заменяет username в адресной строке на актуальный без перезагрузки; это сохраняет работу ссылки при смене ника и исправляет произвольное значение. Прежний формат `/shared-list#<token>` продолжает работать. API пока возвращает прежний `share_path`; клиент формирует новый формат для окна «Поделиться» и публичного профиля.

Токен — 32 случайных криптографических байта, Base64URL без padding, 43 символа. Фрагмент не отправляется веб-серверу в URL или Referer; поэтому токен остаётся после `#`, а не в пути. Предпросмотр и получение изображений используют фиксированные POST-пути с токеном в JSON-теле. Токен хранится в приватной строке списка для повторного копирования владельцем; GORM-логи выключены, контроллеры не логируют тело, токен или сырой текст ошибок. У публичного списка ссылка намеренно доступна в публичном профиле.

Гостевой DTO не содержит email, owner_id, revision, внутренних статусов бронирования или приватных URL изображений. Изображения загружаются по мере появления карточек на экране через POST, выдаются как нормализованный JPEG и отображаются через временный blob URL. Запрос отменяется, blob освобождается при уходе со страницы. Нет внешних запросов к изображению магазина. Ответы `no-store`; гостевые API — `X-Robots-Tag: noindex, noarchive`, `Referrer-Policy: no-referrer`. Ссылочный экран дополнительно получает `noindex/nofollow`; публичный профиль показывает только открытые списки.

## Хранение и конкурентные изменения

Goose `004_wishlists.sql` добавляет `wishlists`, `wishlist_wishes`, уникальный `(id, owner_id)` для желаний и `wishes.lists_version` по умолчанию 1. Предыдущие желания, цены, изображения, ссылки и аккаунты не меняются. Миграция Up/Down и обновление существующей версии 3 проверены на изолированной БД. Rollback списков не удаляет желания/изображения.

Членство имеет PK `(list_id, wish_id)`. Два составных FK через owner_id запрещают связь желания и списка разных владельцев даже на уровне БД. Каскады удаляют только членство при удалении списка/желания; не само желание при удалении списка.

Контроллер → `services.Lists` → `repositories.Lists` с существующими Base/Executor и retry-транзакциями CockroachDB. Создание желания с выбранными списками входит в ту же транзакцию, что желание, ссылки и изображение. Неверный/чужой выбранный список откатывает всё, без «осиротевшего» желания.

- Изменение полей, очистка, удаление и замена ссылки требуют актуальный revision. Мутации списка блокируют строку и увеличивают revision; изменение состава и глобальное удаление желания тоже меняют его. Конкурентное редактирование одного revision даёт один успех и один `409 list_changed`.
- Замена всех списков желания использует отдельный lists_version, чтобы не восстанавливать устаревшие связи после очистки/удаления из другого окна. Добавление, удаление, очистка и копирование связей меняют эту версию. Все выбранные списки проверяются атомарно.
- Копирование — одна транзакция создания списка и `INSERT … SELECT` членства. Авторизация гостевого чтения и чтение содержимого выполняются в общей транзакции; изображения проверяют token, visibility и членство непосредственно в SQL.

## API

Приватные ответы имеют `Cache-Control: no-store`. Мутации требуют настроенный Origin, `X-Wishix-Request: 1`, JSON и отсутствие `Sec-Fetch-Site: cross-site`. Неизвестные поля и хвостовые JSON-значения запрещены.

| Путь | Назначение |
|---|---|
| `GET/POST /api/lists` | Списки владельца / создание |
| `GET/PUT/DELETE /api/lists/{id}` | Список с желаниями / поля / удаление |
| `POST /api/lists/{id}/copy` | Копия с заданным title |
| `POST /api/lists/{id}/share-link` | Замена ссылки с revision |
| `POST /api/lists/{id}/wishes` | Добавить wish_ids, без дубликатов |
| `DELETE /api/lists/{id}/wishes` | Очистить с revision |
| `DELETE /api/lists/{id}/wishes/{wishID}` | Удалить только связь |
| `GET/PUT /api/wishes/{id}/lists` | list_ids/version / атомарная замена |
| `POST /api/public/lists/view` | Гостевой просмотр по token |
| `POST /api/public/lists/image` | JPEG по token и wish_id |
| `GET /api/public/profiles/{username}` | Только публичные списки |

`POST /api/wishes` дополнен необязательным `list_ids`; работает и в multipart JSON-поле `wish`. Формат полей списка: `title`, `description`, `event_date` (ISO YYYY-MM-DD или null), `visibility` (`private/link/public`); обновление включает `revision` и полный набор настроек. Пустое описание и null-дата очищают соответствующие поля. Управление членством: `list_ids` и `version`. Ошибки — 400 для полей/недопустимого выбора, 401 без сессии, 403 CSRF, 404 при отсутствии доступа, 409 при устаревшей версии, 503 при сбое БД.

## Рабочие ограничения — предлагается

Название списка 1–120 символов Unicode, описание до 2000, дата 0001–9999 без времени и сдвига часового пояса. Тело приватной мутации до 64 КиБ, гостевой — 4 КиБ; за один запрос выбора — до 1000 ID, дубликаты объединяются. Существующие ограничения POST желания 48 КиБ/изображения сохраняются. Нет искусственного лимита количества списков, постоянного размера списка или общего количества желаний. Пагинация больших коллекций остаётся будущей задачей.

## Проверки

- Интеграционные Go-тесты: права/CSRF/валидация, общие ID, повторное добавление, копирование без дублей и даты, удаление/очистка без потери желаний, каскады, атомарный выбор списков, конфликт версий и конкурентное редактирование, гостевые DTO/изображения, публичный профиль, закрытие и замена ссылки. Отдельно проверен апгрейд с существующими желаниями, ссылками и изображениями.
- `front/tests/lists.browser.mjs` работает **только** с `compose.auth-test.yaml` на localhost:5174 и Mailpit на 8026. Регистрирует изолированный тестовый аккаунт, проходит управление через UI, гостевой просмотр с изображением, копирование, очистку, смену состава и конфликт вкладок. Удаляет свои тестовые списки и желания. Playwright/Chrome нужны в окружении; `PLAYWRIGHT_MODULE` позволяет указать установленный модуль. Команда: `node front/tests/lists.browser.mjs`.
- `front/tests/shared-link.browser.mjs` перехватывает API и проверяет формат ссылки, исправление ника, старый адрес, недействительный токен и отсутствие токенов в сетевых URL. Его можно запустить на локальном Vite с Playwright/Chrome; `WISHIX_TEST_ORIGIN` меняет адрес приложения.
- 90 состояний в браузере: обзор, форма, список, управление, редактирование и гостевой экран × EN/RU/RO × 320/390/768/1024/1440. Проверяются overflow, touch-цели, локализация, ошибки Vue и восстановление фокуса. Регрессия импорта — `front/tests/wish-import.browser.mjs`.
