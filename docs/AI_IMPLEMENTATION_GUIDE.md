# Codex / AI — практическое руководство по реализации UI

## 1. Перед любым UI-заданием

1. Прочитать существующие `AGENTS.md` и `docs/PROJECT.md`.
2. Прочитать `docs/DESIGN_SYSTEM.md`, `docs/RESPONSIVE_AND_SCREENS.md`, `docs/ASSET_MANIFEST.md`.
3. Посмотреть `design/reference/original-desktop-mobile.png` и `design/reference/approved-brand-board.png` **как изображения**, а не только по именам файлов.
4. Проверить `design/tokens.css`, переиспользовать токены и существующие компоненты.
5. Не менять архитектуру/стек только из-за наличия статического `preview/`.

## 2. Готовая задача для первого этапа

> Реализуй адаптивную оболочку интерфейса Wishix на выбранном в проекте стеке. Сначала прочитай `AGENTS.md`, `docs/PROJECT.md`, `docs/DESIGN_SYSTEM.md`, `docs/RESPONSIVE_AND_SCREENS.md`. В качестве визуального эталона используй `design/reference/original-desktop-mobile.png` и `design/reference/approved-brand-board.png`. Примени дизайн-токены из `design/tokens.css`. Сделай desktop layout с сайдбаром и mobile layout с нижней навигацией. Построй переиспользуемые компоненты: Button, Card, Navigation, Hero, ListCard, WishCard и responsive AppShell. Продуктовую логику и названия пунктов меню бери из `docs/PROJECT.md`, не из демонстрационного скриншота. Выполни проверку на ширинах 320, 390, 768, 1024 и 1440 px. Сделай скриншоты 390 и 1440 px и сверь с эталоном. Не меняй фирменный стиль без отдельного согласования.

## 3. Практика поэтапной разработки

- Шаг A. Импортировать токены и графические ресурсы; создать базовые компоненты, определить состояния.
- Шаг B. Реализовать один экран с настоящей компоновкой и заглушками данных, **не включая новые продуктовые функции**.
- Шаг C. Проверить responsive, клавиатуру, контраст, длинные строки, отсутствие изображений.
- Шаг D. Провести визуальное сравнение и согласовать расхождения.
- Шаг E. Перенести готовые компоненты в остальные согласованные экраны.

## 4. Ограничения изображений

Включённые SVG-ресурсы — **самостоятельные векторные перерисовки**. Они похожи на оригинальный знак, но не идентичны пиксельно. Не объявлять их оригинальным logo master. Не генерировать каждый раз новый логотип с другим бантом/сердцем. Оригинальный растрический логотип для сверки — `design/reference/original-logo-crop.png`.

Демо-карточки, картинки, имена, цены, валюта и некоторые пункты навигации из макета — иллюстративные. Они не определяют доменную модель и business rules.

## 5. Чеклист приёмки PR

- [ ] Новый UI использует единую палитру и Inter.
- [ ] Токены не дублируются новыми HEX без причины.
- [ ] Области desktop/mobile соответствуют композиции референса.
- [ ] На ширинах 320, 390, 768, 1024, 1440 px нет горизонтального скролла.
- [ ] Mobile CTA и навигация не перекрываются клавиатурой и safe area.
- [ ] Есть фокус, hover, disabled и ошибки; элементы доступны с клавиатуры.
- [ ] Основные кнопки и касаемые действия не меньше 44×44 px.
- [ ] Есть empty/loading/error без визуального разрушения сетки.
- [ ] Заголовки и поля корректны с длинными строками RU/RO/EN.
- [ ] Имя, цена, валюта и демонстрационные объекты из картинки не стали бизнес-логикой.
- [ ] Нет e-commerce корзины/checkout и новых функций без требований.
- [ ] Сделаны сравнительные скриншоты 390 и 1440 px.
- [ ] Изменения дизайн-системы оформлены отдельно и согласованы.
